At Runo, both Cloud Telephony (virtual numbers over internet) and SIM Telephony (cellular calling) were already established features. However, users faced a major operational bottleneck whenever they needed to switch between calling modes.

Problem & Context

Previously, the application architecture enforced a binary mode at login or session initialization. If an agent needed to dial via Cloud Calling for specific leads and switch to SIM Calling for others, they were forced to:

  1. Log out or destroy the current application session.
  2. Re-authenticate or select a different profile configuration.
  3. Re-initialize local state, local databases, and sync queues.

This interrupted active dialing workflows and caused friction for sales teams managing hybrid calling setups.

Solution & Architecture

Instead of treating Cloud and SIM calling as isolated application states requiring app re-initialization, I built a single-session Hybrid Telephony orchestration engine.

flowchart TD
  ActiveSession[Active User Session] --> Engine[Hybrid Orchestration Engine]
  Engine -->|Dynamic Switch| Mode{Calling Mode Selected}
  Mode -->|SIM Calling| SIM[Native Cellular Dialing]
  Mode -->|Cloud Calling| Cloud[Cloud Telephony Service]
  SIM --> SessionRetained[Session & State Maintained]
  Cloud --> SessionRetained

Key Technical Contributions:

  • In-App CallMediumSelector: Designed a seamless UI selector (mobile bottom-sheet / web popup) allowing users to switch calling medium instantly for individual calls or default preferences.
  • Session Retention: Retained local state, Hive caches, and auth tokens during calling mode switches — eliminating login/logout overhead.
  • Bulk Virtual Number Assignment: Allowed admins to configure hybrid permissions and virtual number allocations for teams from the admin interface.
  • Unified Analytics & Reporting: Threaded the callMedium metadata through call logs, deleted logs, scheduled reports, and analytics exports to ensure accurate breakdown between SIM and Cloud calls.
