What it does

Before this work, Runo’s app already had both calling paths built: native SIM-based call tracking, and cloud virtual numbers over Airtel IQ. They just couldn’t be used together. An account was configured for one or the other — a customer on SIM tracking had no access to cloud calling features, and vice versa. Switching which mode an account used, or adding a virtual number, meant reconfiguring the account itself, not flipping a setting in the app.

The fix unifies both into one account-level capability: a single account can use SIM tracking and cloud telephony simultaneously, in the same session, rather than being locked into whichever one it was set up with. “Hybrid” now describes what actually happens — both paths available together — instead of a runtime switch between two modes that were still, underneath, exclusive.

Constraints

  • Both calling paths must be usable on the same account at the same time, not just switchable without reconfiguration
  • Same behavior on Android, iOS, and admin web
  • Availability gated by role permissions and virtual-number allocations
  • Workflow layer must not assume low-level transport details of each driver

Decisions & tradeoffs

  1. Single enum (SIM / Cloud / Hybrid) replacing the account-level either-or flag
  2. Session-preserving orchestrator that lets both drivers coexist without resetting the user session
  3. CallMediumSelector for persistent defaults or per-call overrides once both paths are available
  4. callMedium metadata on outbound events, activity logs, exports, and dashboards, so reporting reflects which path a given call actually used

Full diagram

Tradeoffs: letting two drivers be active on one account at once needs careful concurrent-state handling that a strictly-exclusive model never had to deal with. Moving to a strict enum also required a one-time cleanup of legacy accounts sitting in inconsistent/invalid mode states from the old either-or setup.

What it demonstrates

  • Correcting a product limitation that had been built into the account model, not just the UI
  • State-machine modeling for a capability moving from mutually-exclusive to simultaneous
  • End-to-end attribution so reporting matches how calls actually happened, not which mode the account was nominally in
