Product Analytics Pipeline

Tracking calls were scattered through Flutter screens, so staging events polluted production dashboards, re-renders fired duplicates and offline activity was dropped. I built one typed analytics layer over Amplitude that fixes all three. It carries ~15M events a month and has reprocessed 45M in one run.

What it does

Behavioral tracking used to live as ad-hoc Amplitude calls inside feature UI. That produced three failure modes: sandbox events in production dashboards, duplicate .identify() / event spikes on re-renders, and one HTTP request per high-frequency action on flaky mobile networks.

I replaced them with a single ProductAnalytics facade: feature code calls domain methods; the facade owns schema validation, environment routing, deduplication, and batching.

The constraints, design decisions and outcomes are in the full case study.

What it demonstrates

  • Product-analytics infrastructure design (taxonomy, identity, environment isolation)
  • Offline-first client buffering and idempotent event emission
  • Separating vendor SDKs from feature code so destinations can change without rewriting screens
