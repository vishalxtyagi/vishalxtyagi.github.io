Case study

Flutter web admin migration with no downtime

Shared validation, steppers, and dirty-check guards while ops stayed online

Migrating the Flutter web admin tools while ops kept using them: client-side sheet validation, reusable wizards, and unsaved-change guards.

1 min read

Challenge
Every admin page in the Flutter web app had its own upload, mapping and validation code, and closing a dialog could wipe a half-finished mapping.
Approach
Shared browser-side sheet validation, one import wizard and an unsaved-changes guard, moved over one module at a time while ops kept working.
Impact
Core modules moved with no scheduled downtime, and the integration dialog now carries 7 CRM connectors: Zoho, Salesforce, HubSpot, Facebook Lead Ads, WhatsApp Business, S3 and GCS.
Migration style
Incremental module cutovers
Shared primitives
SheetValidationUtil, CustomStepper, dirty-check

Problem

Admin views accumulated three structural issues:

  1. Duplicated ingestion plumbing: parse, map, validate, and error UI rewritten per page
  2. Silent form loss: complex mappings vanished on accidental modal dismiss
  3. Fetch churn: wizards re-queried org metadata on every step

Constraints

  • Ops had to keep using the tools during migration
  • Large sheets needed fast client-side pre-validation
  • Validation contracts had to stay aligned with existing CRM schemas
  • Scope is the Flutter-web admin surface specifically. Runo also runs a separate, independently-managed Vue.js admin module untouched by this migration
  • Bulk customer/allocation mutations run through AWS Lambda rather than a monolith endpoint, for cost isolation and reliability under spiky admin traffic

Approach

Patterns

  1. SheetValidationUtil: column presence, types, length bounds in-browser
  2. wrapDialogWithDirtyCheck: intercept dismiss/navigation with unsaved edits
  3. CustomStepper: one wizard shell for ingestion flows
  4. Normalized domain cache: roles/processes loaded once per flow

Outcomes

  • Core modules moved without a scheduled admin blackout
  • Accidental dismissals stopped wiping multi-field mappings
  • Later CRM integration UIs reused the same upload/validation contracts
  • API key management for downstream integrations (Meta, WhatsApp Business API, HubSpot, Zoho, Salesforce) lives on this surface, inheriting the same primitives

Velocity claims like “50% faster” are omitted here without a measured baseline. The durable win is shared primitives that new admin flows inherit.
