Single-Session Multi-Channel Calling

How the hybrid telephony work moved channel selection out of session init — enum state, session-preserving driver swaps, and callMedium attribution across logs and analytics.

Situation

Sales and ops teams called through two paths — cloud virtual numbers and native cellular. Channel mode was a flag baked into session creation:

flowchart TD
  LegacySession[Session Instantiation] -->|Hardcoded Channel Flag| BoundMode{Bound Channel Mode}
  BoundMode -->|Cellular| CellularSession[Cellular Session]
  BoundMode -->|Cloud| CloudSession[Cloud Session]
  CellularSession -->|Mode Switch| DestroySession[Forced Teardown and Re-Auth]
  CloudSession -->|Mode Switch| DestroySession

Switching modes meant logout, re-auth, and rebuilding local caches and sync queues — and reporting forked into parallel mode branches that disagreed on which medium a call actually used.

Constraint

  • Mode changes must not destroy cached state or auth
  • Same behavior required on Android, iOS, and admin web
  • Availability gated by role permissions and virtual-number allocations
  • Workflow layer must not assume low-level transport details of each driver

Decision

Move mode out of session init and make it runtime state on one session. A session-preserving orchestrator swaps channel drivers; Hive, tokens, and sync queues stay intact.

sequenceDiagram
  participant User as Operator UI
  participant Orchestrator as Session Orchestrator
  participant Driver as Channel Driver
  participant Telemetry as Telemetry and Reporting

  User->>Orchestrator: Request channel action
  Orchestrator->>Orchestrator: Check session and permissions
  alt Cellular
    Orchestrator->>Driver: Cellular intent
  else Cloud
    Orchestrator->>Driver: Cloud virtual service
  end
  Driver->>Telemetry: Tag payload with callMedium
  Telemetry->>User: UI updates; session intact

Primitives

  • Enum model — SIM / Cloud / Hybrid, replacing scattered booleans
  • Driver orchestrator — re-inits transport without resetting the user session
  • CallMediumSelector — default or per-interaction override
  • callMedium attribution — events, activity logs, exports, dashboards

Tradeoff

Rejected alternative: keep mode bound to session and force re-auth on every switch. Simpler state model, but it’s the behavior that was already failing operators — every switch cost a logout and a rebuilt sync queue.

The enum/orchestrator approach traded that for in-session concurrent-state handling complexity, plus a one-time cleanup of legacy invalid mode values already sitting in the data. Both real costs, taken deliberately over reproducing the forced-teardown failure mode.

Evidence (high confidence)

  • Operators change medium without logout
  • Reporting uses one attribution field instead of parallel mode branches
  • Admin permission/allocation changes no longer imply client re-login storms
